\section{引言}

大型语言模型正在从对话系统演变为能够调用外部工具、读取环境状态并连续采取行动的智能体。随着工具调用能力的增强，一个以往被忽视的问题逐渐显现：智能体在完成任务时，可能通过工具参数披露当前操作并不需要的敏感信息。取消订单需要订单编号，却不需要用户的病史；发送通知需要正文，却不需要账户余额。这些字段在工具模式中是可选的，服务端也能正常接收，但披露行为已经超出了当前操作的目的。

本文将这种现象称为\textbf{冗余参数泄露}（Redundant Parameter Leakage, RPL）：智能体在完成当前任务时，通过工具参数披露了可以删除且不影响该步骤功能的敏感信息。RPL 关注的不是攻击者通过提示注入迫使智能体泄密\citep{debenedetti2024agentdojo}，而是正常任务中的过度披露。它也不同于一般的参数错误：工具选择、必填参数和最终状态都可以是正确的，问题仅在于调用中出现了不必要的敏感参数。

这一问题与隐私研究中的"情境"和"目的"密切相关。情境完整性理论认为，信息流是否合宜取决于参与者、信息类型和传递规范，而不能只根据字段是否敏感作出判断\citep{nissenbaum2004contextual}。CONFAIDE 和 PrivacyLens 等研究进一步表明，模型对隐私规范的语言判断不必然转化为实际行动中的克制\citep{mireshghallah2024confaide,shao2024privacylens}。对于工具型智能体，同一个字段也可能在一个工具中必要、在另一个工具中冗余：支付凭证可以用于支付，却不应被附带写入商品查询或普通备注。

\ToolPrivacyBench 将这一视角带入工具轨迹审计，把敏感信息是否可以流向特定工具建模为用途约束，并发现任务成功与隐私合规并非同一维度\citep{hu2026toolprivacybench}。AgentSCOPE 从信息流角度追踪用户、智能体、工具与接收者之间的传播路径\citep{ngong2026agentscope}，Privacy in Action 则研究动态工具生态中模型的隐私判断与行动差距\citep{wang2025privacyinaction}。这些工作共同说明，只检查最终回答，或者只检查任务是否完成，无法覆盖智能体执行过程中的参数级披露。

然而，将现有工具调用任务转化为可复现的 RPL 数据并不是一次简单的格式转换。不同来源提供的参考证据并不相同：有的给出用于描述目标状态的任务动作，有的给出多轮参考调用，有的保存逐次 API 请求与结果，有的提供通过环境验证的方案执行记录。它们对用户身份、可见工具、轨迹完整性和最终状态的表达方式也各不相同。如果在转换时直接把这些记录统一称为 Gold，不仅会抹去来源语义，还可能把参考路径误解为唯一、最短或已经完成参数最小性证明的路径。

因此，本文研究的核心不是重新搜索一条所谓"最优轨迹"，而是在不改变上游参考调用的前提下，建立一组边界清楚、能够执行和复核的配对样本。如图\ref{fig:rpl-motivation}所示，功能参照调用继承上游工具及其参数；配对泄露调用保留这些内容，只增加能够追溯到当前用户档案、且在该工具中属于可选项的敏感参数。两者的差异由此集中在"是否发生冗余披露"，而不会与工具选择错误或必填参数缺失混在一起。

围绕这一目标，本文回答三个问题：

\begin{enumerate}[label=\textbf{RQ\arabic*:}]
  \item 如何在保留来源语义的同时，将四种异构基准统一为可审计的任务、工具、实体和调用表示？
  \item 如何保证敏感字段属于正确用户，并使新增泄露参数满足"模式中存在、当前调用可选、取值有来源"三个条件？
  \item 如何区分来源一致性、可执行性与最终状态正确性，从而避免把一种验证证据夸大为完整的 Gold 证明？
\end{enumerate}

本文的主要贡献如下：

\begin{enumerate}
  \item 提出参数级冗余泄露的配对评测形式，使功能参照调用与泄露调用只在可选敏感参数上产生可计算的差异。
  \item 分析四个公开工具调用基准的原始任务和验证机制，并据此设计保留来源差异的适配与审计流程。
  \item 构建包含 328 条任务的 RPL 数据，逐条提供工具模式、用户实体、功能参照调用、配对泄露调用和来源证据。
  \item 将结构校验、来源重放、环境执行和最终状态验证分层报告，并明确上游参考调用、确定性授权规则及合成可选参数的适用边界。
\end{enumerate}

本文不宣称已经获得人工业务授权意义上的最终 Gold，而是提供一个透明、保守、可重复运行的参数级隐私评测基础。下文依次介绍相关研究、源基准、数据构造、验证结果与局限。
